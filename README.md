# BetterAuth VATSIM Connect SSO

This is a basic implementation of BetterAuth in Next.js 16 using VATSIM's Connect SSO.

More details about BetterAuth can be found in their [documentation](https://www.better-auth.com/docs/introduction). 

## Running

### 1. Database

Start a MySQL database for development using Docker:

```shell
pnpm db:up
```

This starts a MySQL 8.4 container (see `docker-compose.yml`) with a `betterauth_vatsim` database already created. Stop it with `pnpm db:down` (add `-v` to also delete the data volume).

### 2. Environment variables

Copy `.env.example` to `.env` and fill in your VATSIM Connect client credentials (create them on the VATSIM [sandbox](https://vatsim.dev/services/connect/sandbox) for development). Also set a `BETTER_AUTH_SECRET` of at least 32 random characters:

```shell
cp .env.example .env
openssl rand -base64 32 # use the output as BETTER_AUTH_SECRET
```

### 3. Schema

Push the auth schema to the database:

```shell
pnpm db:push
```

### 4. Start the app

```shell
pnpm install
pnpm dev
```

The web server will then be available at `http://localhost:3000`.

## How it Works

A custom OAuth client is setup [here](/lib/auth.ts) using the GenericOauth plugin from BetterAuth. This uses `mapProfileToUser` to fill in the session with VATSIM data as well as user data.

The auth instance is created lazily (on the first request that needs it), so a database or environment failure only affects requests that actually use auth instead of crashing every route at module load.

There is also an `additionalFields` object on the `user` object that declares additional fields for data passed by VATSIM. The `cid` (VATSIM membership ID) is stored as its own column; the local user `id` is generated by BetterAuth and is not coupled to the VATSIM CID.

Because `overrideUserInfo` is enabled, the VATSIM data (ratings, division, region, ...) is re-written from a fresh VATSIM response on **every** sign-in, so rating changes and division transfers are picked up automatically.

The VATSIM OAuth callback is handled at `/api/auth/callback/vatsim` (the standard BetterAuth social callback route). PKCE is disabled because VATSIM Connect does not support it.

If you change the structure of the user fields, you'll need to push your changes to the database by running the following:

```shell
pnpm dlx @better-auth/cli generate # generates the auth schema - you may have to overwrite the old one
pnpm db:push # pushes the changes to the database - if you remove anything it will ask for additional information
```

## Authenticating and Sessions

### Server Side and Client Side Sessions

An example of accessing the session both server side and client side can be found in the following files:

- [Server Side](/app/page.tsx)
- [Client Side](/components/client-side-session.tsx)

### Login and Logout

Examples of logging in and out can be found in the [auth-buttons component](/components/auth-buttons.tsx). After login the browser is redirected to VATSIM's authorization page, and after logout the page is refreshed so the server-rendered session is up to date.

BetterAuth offer a multitude of different features, including [integration guides with other frameworks](https://www.better-auth.com/docs/integrations/next) and using different [databases](https://www.better-auth.com/docs/adapters/mysql) and [adapters](https://www.better-auth.com/docs/adapters/drizzle).
